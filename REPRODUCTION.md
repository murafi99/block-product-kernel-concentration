# Reproduction guide

## 1. Environment

```bash
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

Everything here runs on CPU with a dense, gate-level NumPy statevector simulator
(`theory/simcore.py`) — no GPU, no external quantum-computing library. Block sizes
are capped at b≤8 in practice (2⁸=256-dimensional dense statevectors), well above
what any experiment in this repo actually uses (b≤6).

## 2. Fast path: verify the pipeline works

```bash
pytest tests/ -q                        # ~30s, 69 tests
python reproduce_all.py --scale smoke   # a few minutes total
```

This reproduces the *shape* of every result (the right ordering, the right sign of
every deviation) but not the paper's precision — smoke-scale configs use small
sample counts and shallow circuit depth specifically so the pipeline finishes fast.
Do not compare smoke-scale numbers to the tables in the paper; compare them to the
tables in this file's §5, which are regenerated at smoke scale.

## 3. Full path: paper-precision numbers

```bash
python reproduce_all.py --scale full
```

Or run each experiment individually against its paper-scale config in `configs/`:

```bash
python experiments/exponent_sweep.py --config configs/exponent_sweep.yaml
python experiments/construction_stress_test.py --config configs/stress_test.yaml
python experiments/ranking_agreement.py --config configs/ranking.yaml
python experiments/phase_diagram.py --config configs/phase_diagram.yaml
python experiments/interpolation.py --b 2 --depth 32 --n_pairs 20000
```

**Expected runtime** (single modern CPU core, no parallelism attempted in this
repo — trivially parallel across seeds/blocks if you want to speed it up):

| Experiment | Rough runtime | Dominant cost |
|---|---|---|
| A, b=2..5 | a few minutes each | `n_pairs` × `depth` gate applications per seed |
| A, b=6 | ~10 minutes per seed | 2⁶=64-dim statevector, `depth`=32, `n_pairs`=20000 |
| Stress test | seconds | D=2 only, no depth loop |
| B (ranking) | tens of minutes | trials × 2 quadruplet members × per-n circuit cost |
| C (phase diagram) | up to ~1 hour | full (block × n × N_shots) grid, `trials_per_cell` each |
| D (interpolation) | a few minutes | single b=2 sweep over 5 values of p |

If this is too slow for your machine, reduce `n_pairs`/`trials_per_cell`/`depth`
in a copy of the relevant config — the smoke-scale overrides in
`reproduce_all.py`'s `--scale smoke` path are one such example to copy from.

## 4. Design-assumption verification (do this before trusting any exponent table)

Before comparing any measured exponent to `c(b)`, the per-block average-state
purity is checked against its 1-design target `1/D` (`theory/simcore.py::
average_state_purity`, wired into `exponent_sweep.py`'s `purity_dev` column). This
caught a real problem during the original campaign: at depth L=8, b=1's purity
measured 0.63–0.66 against a target of 0.5 — a ~30% deviation, meaning the
1-design assumption (A3) had failed outright for that circuit.

A depth sweep (rerun via `experiments/exponent_sweep.py` at L=8,16,32,64 for a
given b, editing `depth` in the config) shows b=2 converging monotonically toward
its target while b=1 does not converge at all — this is not insufficient depth,
it is the structural fact of **Corollary 1.2**: a single continuous data
parameter parameterizes only a 1-dimensional curve on the 2-real-dimensional Bloch
sphere, a measure-zero subset that can never equal an exact 2-design at any finite
or infinite circuit depth, using data-marginal randomness alone (see
`theory/simcore.py::brickwall_cnot_ring`, which is a documented no-op for a single
qubit — there is no entangling gate available to scramble it toward Haar
statistics regardless of depth).

**Consequence for anyone extending this repo:** do not add a "b=1 confirms c(1)"
result using the standard mixing-layer circuit family — it is provably unable to
show that, no matter how much compute you throw at it. Use the `b1_structural`
path in `exponent_sweep.yaml` (bare RX(x), or digitizing) instead, both of which
have closed-form target values to check against.

## 6. Preregistration statement

The A=0.75 phase-diagram boundary in `configs/phase_diagram.yaml`
(`preregistered_agreement_boundary: 0.75`) was fixed in that file before
`experiments/phase_diagram.py` was run against it in the original campaign — the
boundary-extraction code (`extract_boundary` in `phase_diagram.py`) reads this
value from the config rather than having it hard-coded in the analysis code, so
changing it after the fact is visible as a config diff, not a silent code change.

## 7. What "full-scale" will and will not match exactly

Re-running `--scale full` will not reproduce the paper's numbers to the last
decimal (different RNG draws, possibly different hardware-dependent floating-point
summation order at the 1e-12 level), but should reproduce every qualitative and
approximate-quantitative claim: the direction and rough size of every relative
error in Experiment A's table, the ordering in Experiment B's ranking curves, and
a goodness-of-fit for the arcsine-law heuristic in the same rough range (median
error on the order of 0.01–0.03, worst-case outliers up to roughly 0.2, per
Section 7.4 of the paper) — if a full-scale re-run gives a qualitatively different
picture (wrong sign of a deviation, wrong ordering, heuristic error an order of
magnitude off), that is worth investigating as a real discrepancy, not smoothing
over, per the same protocol this repo's own campaign followed
(`FINAL_REPORT.md` §4, §7, §9).
